# 📋 Специфікація Вимог (Requirements Specification)

## 1. Функціональні Вимоги

### 1.1 Управління Користувачами (FR-U)

#### FR-U-001: Реєстрація Користувача
- **Опис:** Новий користувач повинен мати можливість зареєструватися
- **Акторы:** Анонімний користувач
- **Передумови:** Користувач має доступ до веб-сайту
- **Основні кроки:**
  1. Користувач заповнює форму (email, пароль, ім'я, прізвище)
  2. Система валідує дані
  3. Система створює новий обліковий запис
  4. Користувачу надсилається email для підтвердження
  5. Користувач підтверджує email
- **Результат:** Облікового запис активовано, користувач може логінитися
- **Альтернативні сценарії:**
  - A1: Email вже зареєстрований → помилка
  - A2: Пароль занадто слабкий → помилка з пропозиціями

#### FR-U-002: Автентифікація
- **Опис:** Зареєстрований користувач повинен мати можливість логінитися
- **Механізм:** JWT токени
- **Сесія:** 24 години
- **Refresh token:** 30 днів

#### FR-U-003: Управління Профілем
- **Опис:** Користувач може переглядати та редагувати свій профіль
- **Поля:** Ім'я, прізвище, аватар, біографія, контакти
- **Права:** Користувач може редагувати тільки свій профіль

### 1.2 Управління Організаціями (FR-O)

#### FR-O-001: Створення Організації
- **Типи:** FEDERATION, LEAGUE, CLUB, ACADEMY
- **Права:** Тільки адміністратори
- **Поля:** Назва, тип, країна, міст, адреса, логотип, опис
- **Результат:** Організація створена, їй присвоєно ID

#### FR-O-002: Управління Членами
- **Додавання:** Керівник організації може запросити користувачів
- **Видалення:** Керівник може видалити члена
- **Ролі:** Admin, Manager, Viewer
- **Сповіщення:** Користувачу надсилається запрошення

### 1.3 Управління Гравцями (FR-P)

#### FR-P-001: Створення Профілю Гравця
- **Вимог:** Користувач має бути членом клубу
- **Поля:** 
  - Персональні: Ім'я, прізвище, ДН, національність
  - Фізичні: Зріст, вага, біотип
  - Футбольні: Позиція, спеціалізація, сильна нога
  - Документи: Номер реєстрації, паспорт
  - Контракт: Початок, закінчення

#### FR-P-002: Статистика Гравця
- **Відстеження:** Матчі, голи, асисти, жовті/червоні карточки
- **За сезон:** Вся статистика розраховується по сезонах
- **Оновлення:** Автоматично при закінченні матчу
- **Доступ:** Публічно доступна (з обмеженнями)

### 1.4 Управління Матчами (FR-M)

#### FR-M-001: Розпис Матчів
- **Планування:** Матчі планируються в дати, часи, місцях
- **Ліга:** Матчі належать лізі
- **Команди:** Домашня та гостьова команди
- **Статус:** SCHEDULED → LIVE → FINISHED
- **Скасування:** З коментарем про причину

#### FR-M-002: Live Scoring
- **Real-time:** Оновлення в реальному часі (WebSocket)
- **События:** Голи, карточки, замени
- **Деталі:** Час, гравець, команда, мінута
- **Доступ:** Публічний

#### FR-M-003: Результати
- **Фінальний счет:** Гроуб - 0, гроуб - 0
- **Події:** Всі голи, карточки, замены
- **Статистика:** Володіння, удари, удари в ворота
- **Архив:** Зберігається назавжди

### 1.5 Управління Лігами (FR-L)

#### FR-L-001: Таблиця Лігі
- **Розрахунок:** За стандартними правилами (3 очки за перемогу)
- **Оновлення:** Автоматично після кожного матчу
- **Позиція:** Команди сортуються за очками, різницею голів, голами
- **Публічна:** Всі можуть переглядати таблицю

#### FR-L-002: Регламент Ліги
- **Правила:** Кількість матчів, формат, призи
- **Штрафи:** Можливість накладати штрафи на команди
- **Апеляції:** Можливість подавати апеляції

### 1.6 Медіа (FR-MD)

#### FR-MD-001: Завантаження Файлів
- **Типи:** Зображення, відео, документи
- **Розміри:** Максимум 500 MB для відео, 50 MB для зображень
- **Формати:** JPG, PNG, MP4, WebM
- **Сховище:** S3 або хмарне сховище

#### FR-MD-002: Обробка Медіа
- **Зображення:** Вирізання, змінення розміру, оптимізація
- **Відео:** Транскодування, генерація превʹю
- **CDN:** Доставка через CDN

### 1.7 Аналітика (FR-A)

#### FR-A-001: Статистика Гравця
- **Метрики:** ВСІ показники з матчів
- **Тренди:** Порівняння з часом
- **Рейтинг:** Ранжування серед гравців

#### FR-A-002: Статистика Команди
- **Показники:** Середній вік, найкращі гравці
- **Форма:** Останні 5 матчів
- **Домашні/Гості:** Различные показатели

## 2. Нефункціональні Вимоги

### 2.1 Продуктивність (NFR-P)

- **NFR-P-001:** API має відповідати протягом < 200ms для 95-го перцентилю
- **NFR-P-002:** Веб-додаток повинен завантажуватись < 3 сек на 4G
- **NFR-P-003:** Мобільний додаток повинен займати < 100 MB
- **NFR-P-004:** Система повинна підтримувати 100,000+ одночасних користувачів
- **NFR-P-005:** Live scoring updates мають затримку < 1 сек

### 2.2 Безпека (NFR-S)

- **NFR-S-001:** Всі паролі хешуються з bcrypt (min 12 rounds)
- **NFR-S-002:** Всі з'єднання через HTTPS/TLS 1.3
- **NFR-S-003:** JWT токени підписані RS256
- **NFR-S-004:** Rate limiting: 100 запитів на хвилину на IP
- **NFR-S-005:** CORS налаштовано правильно
- **NFR-S-006:** CSRF захист на всіх формах
- **NFR-S-007:** SQL injection захист (parameterized queries)
- **NFR-S-008:** XSS захист (HTML escaping)

### 2.3 Доступність (NFR-A)

- **NFR-A-001:** WCAG 2.1 Level AA
- **NFR-A-002:** Мобільна адаптивність (responsive design)
- **NFR-A-003:** Підтримка найменше IE11 (або сучасних браузерів)
- **NFR-A-004:** Час відгуку на мобілі < 2 сек

### 2.4 Надійність (NFR-R)

- **NFR-R-001:** 99.9% uptime SLA
- **NFR-R-002:** Автоматичне резервне копіювання щодня
- **NFR-R-003:** Можливість відновлення з резервної копії < 1 години
- **NFR-R-004:** Graceful degradation при збої сервісу
- **NFR-R-005:** Максимум 5 хвилин втрати даних

### 2.5 Масштабованість (NFR-Sc)

- **NFR-Sc-001:** Горизонтальне масштабування всіх сервісів
- **NFR-Sc-002:** БД шардування при необхідності
- **NFR-Sc-003:** Кешування на всіх рівнях
- **NFR-Sc-004:** CDN для статичного контенту

### 2.6 Підтримуваність (NFR-M)

- **NFR-M-001:** Код покритий тестами на 80%+
- **NFR-M-002:** Документація оновлюється разом з кодом
- **NFR-M-003:** CI/CD pipeline для кожного PR
- **NFR-M-004:** Логування на всіх критичних операціях
- **NFR-M-005:** Структурований лог (JSON)
